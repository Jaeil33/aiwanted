# Step 4: ball

## 왜

`/grill-me` Q8(d)·Q13(d). 이 화면의 주인공은 공인데, 계산해 보니 이랬다.

```
릴리스(55ft)   반지름 1.6px   ← 최소값에 걸려 있었다. 계산값은 0.96px
홈플레이트      반지름 5.4px
```

**흰 동그라미 5픽셀.** 조명도 관중도 잔디 줄무늬도 다 있는데 주인공이 이만했다.

## 한 일 (`src/stage/math/pitch.ts` — 순수)

### 크기
`ballRadiusPx(scale) = max(2, scale × 0.121ft × 1.5)`.
step 1이 `f`를 744로 올렸고 여기에 **×1.5 과장**을 얹어 홈플레이트에서 **11.8px**이 된다. 5.4 → 11.8.
원근으로는 거짓말이지만 실제 중계 그래픽도 공을 원근보다 크게 그린다(Q6 a로 허용).

### 회전
`spinOf(구종)` → `{ turns, tilt }`, `seamAngle(구종, 진행도)`.

| 구종 | 바퀴 | 기울기 | |
|---|---|---|---|
| 직구 | +2.6 | 0 | 백스핀 |
| 투심·커터 | +2.4 / +2.2 | 0.35 / −0.5 | |
| 슬라이더·스위퍼 | −2.4 / −2.8 | −0.9 / −1.2 | 옆회전 |
| 커브 | −2.6 | 0.15 | 탑스핀 |
| 체인지업 | +1.8 | 0.2 | |
| 포크 | **+0.4** | 0.1 | 거의 안 돈다 |

**회전축은 기록에 없다.** 구종에서 지어낸 값이다(Q6 a).

## 캔버스 쪽

공 하나를 그리는 순서: 그림자 → **빛무리** → 구체 → **실밥**.

- 빛무리: 하늘 팔레트의 조명 색으로 반지름 2.4배까지. **낮에는 `glow`가 0이라 안 그린다.**
- 실밥: 공에 클립을 걸고 `seamAngle`만큼 돌린 뒤 좌우 호 두 줄. **반지름 4px 아래에서는 안 그린다** —
  그 크기에서는 진흙이 된다. 그래서 멀리서 날아올 때는 흰 공이다가 가까워지면서 돌기 시작한다.
- 잔상 굵기도 같은 배수를 쓴다(공만 커지고 꼬리가 가늘면 따로 논다).

## 확인

`ballRadiusPx(65.1)`이 11~13px 사이, 과장 배수가 정확히 1.5.
트래커 테스트로 **멀 때는 `rotate`를 안 부르고 홈플레이트 근처에서 부른다**는 것까지 못 박았다.
