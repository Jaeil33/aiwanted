# Step 3: living

## 왜

`/grill-me` Q9(b)·Q14(d)·Q18(c)·Q22(b).

캔버스는 **사건이 있을 때만** 다시 그린다. 던지는 1초를 빼면 완전한 정지 화면이었는데,
사용자가 이 화면에서 보내는 시간은 거의 전부가 그 1초 **바깥**이다(TMI를 쓰고 확률을 보는 시간).

Q18에서 상시 rAF 루프는 안 하기로 했다. 그런데 Q14에서 고른 관중 술렁임·조명 호흡은
2.5초에 한 번 다시 그리면 계단처럼 점프해서 고장 난 것처럼 보인다. **둘이 부딪혔다.**

## 답: 움직임을 캔버스 밖으로

CSS 애니메이션은 컴포지터가 돌린다. **JS가 한 줄도 안 돌고**, `prefers-reduced-motion`도 CSS가 스스로 지킨다.

`src/components/StadiumLife.tsx` — 캔버스 **위**에 겹치는 `<div>`.

| | |
|---|---|
| 관중 술렁임 | 같은 점무늬 두 장을 반대 위상으로 5.4초 주기로 밝혔다 어둡혔다 |
| 조명 호흡 | 좌·우 번짐 두 개가 7.5초 주기로 (오른쪽은 −3.2초 엇갈려) |
| 카메라 플래시 | 관중석에 일곱 개. 9.6초 주기로 **1.5%만 켜진다**(한순간) |

움직이는 속성은 `opacity`뿐이라 레이아웃도 페인트도 안 일어난다. 하늘 팔레트가 개수를 정한다 —
**낮에는 조명도 플래시도 안 그린다**(`glow: 0`, `flashes: false`).

## 왜 캔버스 뒤가 아니라 위인가

뒤에 깔면 캔버스 배경이 덮어 버린다. 위에 놓되 **`mix-blend-mode: screen`** 이라 **빛을 더하기만 한다.**
릴리스 순간 공은 관중석 높이에 있는데(지평선보다 18px 위), 흰 공에 빛을 더해도 흰 공이라 가려지지 않는다.

`.tracker`에 `isolation: isolate`를 줘서 이 합성이 페이지 전체가 아니라 트래커 상자 안에서만 일어나게 했다.

## 실제로 확인

해질녘 경기(사직 9/5)를 띄우고 `requestAnimationFrame`을 가로채 셌다.

```
2초 동안 rAF 호출: 0
동시에 돌고 있는 CSS 애니메이션: 13개
mix-blend-mode: screen · pointer-events: none · 부모 isolation: isolate
```

관중석이 계속 술렁이는데 **자바스크립트는 한 번도 안 깨어난다.**
