# Step 3: drop-favourite

## 왜

사용자: **"그냥 내팀 시스템을 없애줘."**

step 1이 잠금을 풀고 나니 응원팀에 남은 일이 둘뿐이었다 — `내 팀` 표 하나, `전체 / OO만` 칩 하나.
그 둘을 위해 지고 있던 것은 이만큼이다.

- `localStorage` 예외 하나(ADR-034가 `ARCHITECTURE.md`의 "브라우저 저장소를 쓰지 않는다"를 뚫었다)
- 읽기·쓰기 실패 대비(사생활 보호 모드)와 같은 탭 구독(`useSyncExternalStore`)
- 팀이 있을 때와 없을 때로 갈리는 화면 네 벌(홈 머리말·홈 제목·팀 목록·팀 머리말)

구단 띠(step 2)가 어느 화면에서나 10구단에 한 번에 닿게 해 준 뒤로는, 응원팀이 없어도 자기 팀 일정까지 두 번이면 간다.

## 지운 것

| | |
|---|---|
| `src/app/useFavouriteTeam.ts` + 테스트 | 저장소 예외가 사라졌다 |
| 홈 | `mineOnly` 상태, `전체 / OO만` 칩, `내 팀` 표, 제목 갈림 |
| 팀 목록 | `내 팀` 표, `응원팀 지우기`, "이 기기에만 남아요" |
| 팀 달력 | `응원팀으로` / `내 팀` 토글 |
| 구단 띠 | `내 팀` 표 |
| `game/paList.gamesOfTeam` | 이 변경으로 부르는 곳이 없어졌다 |

## 함께 고친 것

`TeamScore`의 `mine` / `theirs`를 **`scored` / `allowed`**로 바꿨다. 없앤 개념의 이름이 필드에 남으면
다음에 읽는 사람이 "내 팀"을 다시 찾는다. 뜻은 그대로다 — 달력을 보고 있는 그 팀의 득점:실점.

## 남는 상태

앱은 이제 브라우저 저장소를 **전혀** 쓰지 않는다. `ARCHITECTURE.md`의 원래 규칙으로 돌아왔다.
그래서 홈·팀 목록·팀 달력 테스트에 `expect(window.localStorage.length).toBe(0)`를 박았다.

ADR-039로 적었다(ADR-034를 되돌리고 ADR-038의 응원팀 부분을 대체).
