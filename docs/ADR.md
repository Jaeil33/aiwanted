# Architecture Decision Records

## 철학
- 재미는 과장으로, 신뢰는 계산으로. 숫자는 코드가 정확히 계산하고, 과장은 '만화 모드' 라벨을 달 때만 한다.
- 9/20에 휴대폰에서 끝까지 도는 한 판이 먼저다. 모든 기능은 AI나 데이터가 없어도 동작하는 대체 경로를 가진다.
- 원자료는 우리 것이 아니다. 필요한 최소 요약만 앱에 싣고 출처를 밝힌다.

---

### ADR-001: Next.js 대신 Vite + React SPA
**결정**: Vite 8 + React 19 + TypeScript 6.0 정적 번들. 서버 로직은 `api/` 서버리스 함수 두 개(AI 프록시)뿐이다.
**이유**: 확률 엔진이 브라우저에서 돌기 때문에 서버 렌더링이 필요 없다. 정적 번들은 단일 HTML 아티팩트 미리보기와 어느 정적 호스팅에도 그대로 올라간다. `vite-plugin-singlefile`로 데이터까지 한 파일에 담을 수 있다.
**트레이드오프**: 공유 링크별 OG 이미지를 서버에서 만들 수 없다(공유 카드는 클라이언트 캔버스로 만든다). 하네스 템플릿의 Next.js 예외(page.tsx 등)가 TDD 가드에 적용되지 않으므로 모든 .ts/.tsx에 테스트 파일을 둔다.

### ADR-002: 확률은 정확 계산, 재생만 표본
**결정**: 타석 분포(오즈비 매칭) → 반이닝 마르코프 질량 전파(아웃·주자·타순·득점) → 경기 동적 계획(이닝·점수차·양 팀 타순, 11회 무승부)으로 정확한 확률을 낸다. 볼카운트는 리그 카운트별 투구 결과 표를 매치업에 맞게 보정한 흡수 마르코프 체인이다. 재생(한 구·타석·경기 끝까지)만 시드 난수로 표본을 뽑는다.
**이유**: TMI 효과는 0.1%p 단위로 작다. 몬테카를로 잡음이 효과보다 크면 게임의 핵심 문장("짜장면 하나로 +0.6%p")이 흔들린다. 같은 입력에 같은 숫자가 나와야 공유와 검증이 가능하다.
**트레이드오프**: 주루·병살 확률은 고정 상수(프로토타입 `buildTransitions`)이고, 이후 반이닝은 불펜 합성 선수로 단순화한다. 선수 교체·대타·도루는 모델에 없다.

### ADR-003: 숫자는 엔진, 말은 AI
**결정**: AI는 자유 문장을 `KnobPart`/`MeasuredPart`와 한 줄 해설로 번역하고, 판정 때는 evidence 조회 결과를 설명만 한다. 모든 AI 출력은 `normalize.ts`로 검증(손잡이·대상 조합, 세기 −3~3 정수, 최대 3개, 글자 수)하고, 실패하면 규칙 해석으로 대신한다.
**이유**: 심사 기준인 'AI 활용 적절성'은 AI가 꼭 필요한 곳(엉뚱한 자연어 이해와 설명)에 쓰였는지다. 확률을 LLM이 만들면 틀려도 검증할 수 없다.
**트레이드오프**: 14개 손잡이와 실측 변수 밖의 새 메커니즘은 표현할 수 없다. 규칙 해석은 AI보다 덜 재밌다.

### ADR-004: 실측 변수는 팀-경기 포아송 모델 + 시간 순 검증
**결정**: 2021–2026 정규시즌 팀-경기 행(그 팀의 득점)에 `log μ = 공격(팀·시즌) + 수비(상대·시즌) + 구장 + β·x` 포아송 GLM을 IRLS로 적합한다(요인 효과에만 작은 릿지). x = 기온·바람 세기·경기 전 3시간 강수·낮 경기·주말·원정 이동 거리·휴식일 다음 경기·상대 선발 짧은 휴식·상대 선발 긴 휴식·(참고용) 홈. β는 2021–2025로만 추정하고, 2026 경기에서 이탈도 개선량(경기 단위 부트스트랩 95% 구간)으로 검증한다. 판정: 학습 95% 구간이 0을 벗어나고 2026 개선 구간 하한이 0보다 크면 `real`, 둘 중 하나만 만족하면 `maybe`, 둘 다 아니면 `useless`. 앱은 득점 배수를 리그 평균 타선의 득점 탄력성으로 나눠 공격 벡터 크기로 바꿔 적용한다.
**이유**: 선수 단위로 쪼개면(예: 특정 투수의 낮 경기) 표본이 작아 잡음뿐이다. LG Aimers에서 멘탈·클러치 피처가 모두 효과가 없거나 오히려 점수를 떨어뜨린 교훈이다. 팀-경기는 5천 경기가 넘어 작은 효과도 구간으로 말할 수 있다. 학습·검증 분리는 LG Aimers의 walk-forward 방식 그대로다.
**트레이드오프**: 팀 단위 효과를 모든 타석에 똑같이 나눠 적용한다. 바람 방향·습도·구장 방향은 없다. 고척돔은 날씨 변수를 0으로 둔다. 선발 휴식일은 선발 이름+팀으로 계산해 기록 누락에 약하다.

### ADR-005: 데이터 권리와 실명
**결정**: 네이버 비공식 API·Open-Meteo 원자료와 생성물은 `data/`에만 두고 커밋하지 않는다. 앱에는 장면에 필요한 최소 요약(선수 상대 능력치, 장면 투수의 투구 표본, 장면 상태)만 싣고 화면에 출처를 적는다. 선수는 텍스트 실명만 쓰고 사진·구단 로고·엠블럼 URL은 쓰지 않는다. 실존 선수에 대한 민감한 TMI는 AI와 규칙 양쪽에서 거부한다.
**이유**: 공식 기록 권리는 KBO와 데이터 사업자에게 있고, 비공식 API 원자료 재배포는 분쟁 전례가 있다. 저장소가 공개라서 커밋이 곧 재배포다.
**트레이드오프**: 저장소만 받아서는 앱 데이터를 재현할 수 없다(`npm run data`에 원자료가 필요). 선수 얼굴 없는 연출이 된다.

### ADR-006: AI 프로바이더 3단 구성
**결정**: (1) 아티팩트 미리보기: `claude.use('sample')`의 `json`으로 해석(modelTier `quick`), `tools`로 판정(modelTier `default`). (2) 배포: `api/interpret.ts`, `api/verdict.ts`가 서버 환경변수 키로 Anthropic Messages API를 부른다. 모델은 환경변수 `TMI_MODEL_INTERPRET`(기본 `claude-haiku-4-5-20251001`), `TMI_MODEL_VERDICT`(기본 `claude-sonnet-5`). 입력 80자, 출력 토큰, IP당 분당 호출 수를 제한한다. (3) 없음: 규칙 해석·규칙 판정. 모든 호출은 8초 제한 시간이 지나면 다음 경로로 넘어간다.
**이유**: 미리보기에서는 키 없이 실제 AI를 쓸 수 있고, 배포에서는 투표 참여자 누구나 계정 없이 써야 한다. 해석은 짧은 JSON이라 빠른 모델로 충분하고, 판정은 도구 호출과 설명 품질이 중요하다.
**트레이드오프**: 배포 비용과 남용 위험(호출 제한으로 완화), 프로바이더마다 응답 모양이 다름(normalize로 흡수).

### ADR-007: 허용 의존성
**결정**:
- dependencies: `react`, `react-dom`
- devDependencies: `vite`, `@vitejs/plugin-react`, `typescript@~6.0.3`, `vitest`, `jsdom`, `@testing-library/react`, `@testing-library/dom`, `@testing-library/jest-dom`, `@testing-library/user-event`, `eslint`, `@eslint/js`, `typescript-eslint`, `eslint-plugin-react-hooks`, `globals`, `vite-plugin-singlefile`, `tsx`, `@types/react`, `@types/react-dom`, `@types/node`
- Python(`pipeline/requirements-dev.txt`): `numpy`, `pytest`
**이유**: TypeScript 7은 typescript-eslint가 아직 지원하지 않는다(`<6.1.0`). 차트·상태관리·스타일 라이브러리 없이 캔버스·SVG·useReducer로 충분하다.
**트레이드오프**: 차트와 애니메이션을 직접 그린다.

### ADR-008: 하네스 병렬 실행
**결정**: `0-setup`(스캐폴딩·공용 타입) 뒤에 `1-engine`, `2-data`, `3-stage`, `4-ai`를 각각 별도 git worktree에서 동시에 실행하고, 통합 브랜치에서 합친 뒤 `5-app`, `6-release`를 순서대로 실행한다. 로컬 자동 모드는 권한 우회(`--dangerously-skip-permissions`) 세션 생성을 막으므로, phase는 권한 검사를 그대로 받는 격리 서브에이전트가 `execute.py`와 같은 규칙(step 파일 순서, AC 실행, `index.json` 상태·summary·타임스탬프 기록, step마다 `feat(<phase>): step N — <name>` 커밋)으로 실행한다. `scripts/execute.py`는 사람이 직접 돌릴 때를 위해 Windows 보정(stdin UTF-8 프롬프트, 1시간 제한 시간 기록)을 유지한다.
**이유**: 공용 계약(`src/types`, `src/domain`, 이 문서들)이 먼저 고정되면 네 층은 서로의 코드를 읽을 필요가 없다. 권한 우회 없이도 step 파일·AC·기록이라는 하네스의 검증 구조는 그대로 지킬 수 있다.
**트레이드오프**: step마다 새 세션을 띄우는 대신 phase 단위 세션이라 앞 step의 맥락이 이어진다. 통합할 때 `phases/index.json` 충돌을 손으로 푼다. worktree마다 `node_modules`와 `.venv`를 따로 만든다.

### ADR-009: 만화 모드
**결정**: 만화 모드는 모든 TMI 효과의 로그 오즈를 6배로 키우고 상한을 0.45에서 1.6(최대 약 5배)으로 넓힌다. 화면에 "만화 모드: 효과 6배 과장"을 항상 표시하고, 결과와 공유 카드 이미지 안에도 모드를 새긴다.
**이유**: 현실 크기(±1%p 안팎)는 정직하지만 첫 경험의 '와'가 약하다. 두 모드의 차이 자체가 "쓸모없는 변수는 실제로 작다"는 메시지가 된다.
**트레이드오프**: 과장 수치가 캡처돼 사실처럼 퍼질 수 있다. 이미지 안에 라벨을 새겨 완화한다.

### ADR-010: 휴대폰 우선 단일 테마
**결정**: 390px 세로 화면을 기준으로 설계하고 1024px 이상에서 2단으로 넓힌다. 야간 경기 중계 그래픽의 단일 다크 테마로 고정한다(라이트 테마 없음).
**이유**: 투표가 휴대폰 인증이라 대부분 휴대폰으로 들어온다. 중계 화면의 LED·조명 느낌은 어두운 바탕에서만 산다.
**트레이드오프**: 밝은 곳 가독성은 대비 기준(본문 4.5:1 이상)으로만 보장한다.
