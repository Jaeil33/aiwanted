# UI 디자인 가이드 — 중계 트래커 (ADR-018)

시각 기준 시안: `docs/design/broadcast/` (로비·타석·TMI 카드·결과). 색·글꼴·크기 값의 원본은 시안 `style.css`의 `:root`와 `tracker.mjs`다. 시안에 아직 없는 화면(경기 타석 목록·매치업 찾기·직접 만들기)은 이 문서의 구성을 따르고 16-broadcast-ui 전에 시안에 추가한다. 시안 코드를 import하지 않는다. `docs/design/nightgame/`은 폐기된 시안이다.

## 디자인 원칙
1. **진짜 중계처럼 보인다.** 포수 뒤 투구 트래커, 스코어버그, 타자·투수 자막은 실제 중계 그래픽 문법을 따른다. 사람 인형·만화 연출은 없다.
2. **큰 숫자는 하나만.** 타석 화면은 "그 결과가 나올 확률" 하나만 크게, 경기 승률 변화는 한 줄로 쓴다.
3. **숫자 옆에는 이유가 있다.** 확률 옆에 근거 등급(실측·그럴듯함·상상)을 색 점과 글자로 붙인다. 만화 모드 값은 결과 카드의 한 줄에만 있고 모드 라벨을 단다.
4. **TMI는 카드 한 장.** 해석 출처, 등급, 인용 문장, 손잡이·대상·세기, 이유, "진짜야?"를 한 장에 담는다.
5. **엄지 하나로 끝난다.** 주요 조작은 하단 도크에 둔다. 버튼 높이는 52px, 한 화면에 주요 버튼은 하나다.
6. **움직임은 결과를 알릴 때만.** 투구 궤적, 볼·스트라이크·결과 콜, 숫자 변화, 1,000타석 점, 시트 열기에만 쓴다.
7. **실제 경기가 콘텐츠다.** 실명·시즌 기록·구장·날짜·실제 투구 궤적을 쓴다. 가짜 수치·로고·사진·광고판은 쓰지 않는다.

## 반경·간격·깊이
- 반경: 6px(칩·세그먼트), 8px(입력·목록 행·투구 정보 판), 12px(버튼·카드), 16px(시트 위쪽 모서리·큰 판), 999px(알약). 다른 값은 쓰지 않는다.
- 간격: 4px 단위(4 · 8 · 12 · 16 · 24 · 32). 형제 간격은 `gap`으로 준다.
- 그림자는 떠 있는 시트에만 `0 -20px 60px -20px rgba(0, 0, 0, 0.8)`.

## 화면 구성 (390px 기준)
### 로비 `#/`
1. 상단 바 52px: 브랜드 "TMI 야구"('야구'만 `--accent`), 오늘 날짜(요일).
2. 한 줄 소개: "방금 그 타석, 만약 그랬다면?"
3. **지금 경기**: 가로 스크롤 경기 카드(폭 260px). 진행 중(LIVE 점·이닝·점수)이 먼저, 경기 전은 시작 시각, 끝난 경기는 최종 점수. 누르면 `#/game/:gameId`.
4. 두 칸 버튼: **지난 경기**(날짜 고르기 → 경기 목록) · **직접 만들기**(`#/custom`).
5. **매치업으로 찾기** 입력(타자·투수 이름) → `#/matchup`.
6. **오늘 많이 걸린 TMI** 5줄(효과 이름·대상·횟수). 집계를 못 쓰면 칸 전체를 숨긴다.
7. 출처 한 줄(`--text-3` 11px), 하단 탭바 64px: 경기 · 만든 이유.

### 경기 `#/game/:gameId`
- 스코어버그 머리(팀 색 선, 점수, 이닝, 상태). 진행 중이면 "LIVE · 문자중계 기준 수십 초 늦을 수 있어요".
- 진행 중 타석 행(비활성, 카운트·주자·아웃).
- 끝난 타석 목록(최신순, 행 64px): 이닝 ▲▼ · 타자 vs 투수 · 결과 칩(삼진 `--out`, 볼넷·안타 `--ball`, 범타 `--text-2`) · 주자·아웃 미니 표시 · 득점. 누르면 `#/pa/:gameId/:no`. 사건으로 바꿀 수 없는 타석은 흐리게, "계산할 수 없는 결과".
- 이 경기에서 많이 걸린 TMI 3줄.
- 경기 전: 시작 시각과 예고 선발, "시작하면 여기에 타석이 쌓여요". 오류: "중계를 불러오지 못했어요" + 매치업 찾기·직접 만들기 버튼.

### 매치업 찾기 `#/matchup`
- 타자·투수 입력 두 개(초성·부분 일치 자동완성, 2026 선수). 결과 행: 날짜 · 경기 · 이닝 · 결과 칩. 누르면 그 타석으로. 수집 범위를 한 줄로 밝힌다("8월 1일~9월 19일 경기").

### 직접 만들기 `#/custom`
- 순서: 공격 팀·수비 팀 → 타자(공격 팀 선수 목록 + 검색)·타순 → 투수(수비 팀) → 이닝·초말 세그먼트 → 아웃 점 3개 → 주자 다이아몬드(누르면 켜짐) → 점수 스텝퍼 → 볼·스트라이크 점.
- 도크: "이 상황으로 가기"(`--accent`).

### 타석 `#/pa/:gameId/:no` · `#/pa/custom?s=`
- 스코어버그(상단): 팀·점수·이닝 ▲▼·아웃·주자·볼카운트.
- 트래커 캔버스(폭 100%, 높이 약 300px): 실제 결과 투구를 번호 원으로 미리 찍어 두고 "실제 투구 보기"로 궤적을 다시 날린다. 좌상단 구종·구속 판, 가운데 콜, 아래 자막(타자 이름·타석 방향·타율·OPS | VS | 투수 이름·투구 손·ERA·WHIP).
- 실제 결과 칩: "실제: 삼진"(직접 만들기에는 없음).
- 확률 판: 라벨("김도영 삼진 확률"), 큰 숫자 58px(TMI가 있으면 TMI 값, 옆에 TMI 없음 값 작게), 변화 칩(%p, `--up`/`--down`), 등급 점·글자, 한 줄 "KIA 승리확률 54.3% → 52.1% (−2.2%p)".
- 걸린 TMI 알약(최대 3개, 등급 색 점 + 짧은 문장). 누르면 TMI 카드.
- 도크: TMI가 없으면 "TMI 걸기"(주요) · 있으면 "한 타석 쳐보기"(주요)와 "TMI 추가"(보조). 쳐보는 중에는 주요 버튼이 "건너뛰기".

### TMI 시트
- 아래에서 올라오는 시트(위 모서리 16px). 뒤 화면은 60% 어둡게, 시트 머리에 작은 확률 판("전 → 후", 변화 칩).
- TMI 카드: 머리("AI 해석/규칙 해석", 등급 칩) → 인용 문장(700 18px) → 손잡이 행(방향 아이콘, 이름, 대상, 세기 7칸 점) → 이유 한 줄과 "진짜야?". "진짜야?"를 누르면 카드 아래로 판정(맞는 실측 변수, 학습 효과·95% 구간, 2026 검증, 판정 글자)이 펼쳐진다.
- 거부 카드는 `--out` 1px 테두리, 거부 이유와 바꿔 쓸 예시. 거부된 문장은 TMI 칸을 차지하지 않는다.
- 카드 아래: 입력 줄(52px, 글자 16px, 오른쪽 "걸기"), 글자 수, 예시 칩(가로 스크롤). 거부·실패 때 입력을 지우지 않는다.

### 결과 카드 (타석 화면 위 시트)
1. 쳐본 결과 콜과 헤드라인("삼진!"), 실제 결과 칩(있으면).
2. 1,000타석 점(40×25): 큰 숫자의 사건 색 → 나머지 순서로 채운다. 범례 "1,000번 중 삼진 310번 · TMI 없이 230번".
3. 경기 승리확률 한 줄, "만화 모드(효과 6배)였다면 N%" 한 줄(모드 칩).
4. 도크: "같은 TMI로 다시"(주요) / "결과 카드 공유".

### 만든 이유 `#/about`
- 탭바를 쓴다. 출발점 → 작동 방식(TMI → AI/규칙 → 엔진 → 트래커) → 엔진 신뢰도(Brier 표) → 실측 변수 판정 표 → 데이터 출처와 한계. 본문 폭 최대 62자, 숫자는 `--num`.

### 데스크톱 (1024px 이상)
- 가운데 게임 열(최대 480px, 휴대폰과 같은 구성), 양옆은 `--bg`. 2단 대시보드는 쓰지 않는다.

## 움직임
| 순간 | 방법 | 시간 |
|------|------|------|
| 투구 궤적 | 트래커가 PTS 시간 그대로 그리고 끝에 잔상 궤적과 번호 원을 남긴다 | 약 450ms(느린 공은 2.4배) |
| 볼·스트라이크·결과 콜 | DOM 콜: scale 1.3→1, 머무른 뒤 사라짐 | 900ms |
| 숫자 | 카운트업(소수 첫째 자리) | 600ms |
| 1,000타석 점 | 채우는 비율 easeOutCubic | 1,200ms |
| 시트 | `translateY(100%)`→0 | 260ms |

- `prefers-reduced-motion: reduce`: 궤적 없이 최종 번호 원만, 숫자·점은 최종 상태로 바로 간다.
- 문서가 숨겨지면 트래커 연출을 즉시 끝낸다(ADR-018).

## 투구 트래커 (ADR-018)
- 포수 뒤 망원 시점: 카메라 y −30ft, 높이 4.6ft, 초점 거리는 캔버스 폭에서 계산(시안 `tracker.mjs`).
- 그리는 순서: 관중석 띠(한 번 흐리게 그린 오프스크린) → 외야 벽 → 잔디 줄무늬 → 내야 흙·베이스라인 → 마운드 → 홈플레이트 흙 원·타자석·홈플레이트 → 비네트 → 스트라이크 존(채움 + 3×3 안선 + 테두리) → 궤적 → 번호 원.
- 존 판정 면은 홈플레이트 앞면 y = 1.417ft, 존 위·아래는 행의 `topSz`·`bottomSz`.
- 볼·스트라이크 콜과 결과 글자는 캔버스에 그리지 않는다.

## 아이콘
- 인라인 SVG, stroke 1.5~2, `currentColor`. 야구 요소(다이아몬드, 공, 배트)와 조작(재생, 건너뛰기, 되돌리기, 공유, 검색)에만 쓴다.

## 문구
- 해설위원 톤의 짧은 한국어.
- 버튼: "지난 경기", "직접 만들기", "매치업으로 찾기", "이 상황으로 가기", "실제 투구 보기", "TMI 걸기", "걸기", "한 타석 쳐보기", "건너뛰기", "진짜야?", "같은 TMI로 다시", "결과 카드 공유".
- 확률 변화는 `+0.6%p`, `−0.07%p`, `±0.00%p`. 확률은 소수 첫째 자리까지 `%`.
- 억지 해석: "딱 맞는 규칙이 없어 문장 분위기로 살짝 이었어요."
- 거부: "선수 건강·사생활·범죄 이야기는 계산하지 않아요. 음식·잠·날씨·징크스로 바꿔 보세요."
